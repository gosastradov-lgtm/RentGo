# Отчёт по практике: веб-приложение «Прокат оборудования»

## 1. Цель и задачи
Закрепление навыков проектирования и разработки ПО: от анализа требований до тестирования и публикации.

## 2. Анализ предметной области и аналогов
Прокат спортивного, туристического и строительного оборудования. Аналоги для сравнения (заполнить по результатам изучения сайтов): локальные сервисы проката, Rentman, EZRentOut. Критерии: онлайн-бронирование, проверка доступности, штрафы, роли, учёт склада, статистика.

## 3. Требования
**Функциональные.** Клиент: каталог с поиском и фильтрами, регистрация/вход, бронирование с расчётом цены, статусы (забронировано → подтверждено → выдано → возвращено / просрочено), история аренд. Менеджер: подтверждение, выдача и приём с отметкой состояния, штрафы за просрочку и повреждение. Администратор: каталог, категории, тарифы, пользователи и роли, склад (ремонт, списание), статистика.
**Нефункциональные.** Адаптивный интерфейс; валидация данных (Pydantic + CHECK в БД); корректная обработка пересечений броней; отклик до 2–3 с.

## 4. Архитектура
Трёхуровневая: SPA на HTML/CSS/JS → REST API (FastAPI) → БД (SQLite, переключается на PostgreSQL через `DB_URL`). Аутентификация по Bearer-токену, роли `client`, `manager`, `admin` проверяются зависимостями FastAPI.

## 5. База данных
```mermaid
erDiagram
    USERS ||--o{ BOOKINGS : makes
    EQUIPMENT ||--o{ BOOKINGS : "is booked in"
    CATEGORIES ||--o{ EQUIPMENT : groups
    USERS { int id PK; string email UK; string name; string pw; string role; string token }
    CATEGORIES { int id PK; string name UK }
    EQUIPMENT { int id PK; string name; int category_id FK; float price_per_day; float late_fee_per_day; int qty_total; int qty_repair; int qty_written_off }
    BOOKINGS { int id PK; int user_id FK; int equipment_id FK; int qty; date date_from; date date_to; string status; float total; float fine; string condition; date returned_on }
```
Ограничения: `price_per_day > 0`; `qty_total >= 0`; `qty_repair + qty_written_off <= qty_total`; `date_to >= date_from`; `qty > 0`; уникальны `email` и `categories.name`.

**Доступность.** Свободно = всего − ремонт − списано − сумма `qty` активных броней (booked/confirmed/issued), пересекающихся по датам (`date_from <= new_end AND date_to >= new_start`).
**Расчёты.** Стоимость = (дни включительно) × qty × цена/сутки. Штраф = дни просрочки × qty × штраф/сутки + плата за повреждение. Статус «просрочено» вычисляется, если выдано и дата окончания прошла.

## 6. API (основное)
`POST /api/register|login`, `GET /api/equipment?q&category_id&max_price&start&end`, `POST /api/bookings`, `GET /api/bookings/my`, `POST /api/bookings/{id}/cancel`, `POST /api/manager/bookings/{id}/confirm|issue|return`, `PUT /api/equipment/{id}/stock`, `GET /api/admin/stats`, `PUT /api/admin/users/{id}/role`. Документация Swagger: `/docs` (подходит для Postman).

## 7. Тестирование
Автотесты: `pytest`. Ручные проверки:
| № | Сценарий | Ожидание |
|---|---|---|
| 1 | Регистрация с неверным email, коротким паролем | 422 |
| 2 | Бронь с датой окончания раньше начала | 422 |
| 3 | Бронь с датой в прошлом | 422 |
| 4 | qty = 0 | 422 |
| 5 | Бронь на пересекающиеся даты при нехватке единиц | 409 |
| 6 | Бронь на следующий день после окончания чужой | 200 (граничное значение) |
| 7 | Клиент открывает рабочее место менеджера | 403 |
| 8 | Выдача без подтверждения | 409 |
| 9 | Возврат с просрочкой и повреждением | штраф рассчитан |
| 10 | Ремонт + списание > всего на складе | 422 |
| 11 | Время отклика каталога | < 2 с |

## 8. Руководство пользователя
**Клиент:** «Войти» → регистрация → в каталоге выбрать даты, нажать «Найти», затем «Забронировать» → «Мои аренды» (статусы, отмена).
**Менеджер:** вкладка «Менеджер»: Подтвердить → Выдать → Принять (ввести состояние и штраф за повреждение).
**Администратор:** «Админ» (склад, добавление позиций, роли), «Статистика» (графики).

## 9. Запуск и публикация
```
pip install -r requirements.txt
uvicorn main:app --reload      # http://localhost:8000
pytest
```
Тестовые учётки: `admin@rental.local / admin123`, `manager@rental.local / manager123`. Публикация: Render/Railway/VPS (`uvicorn main:app --host 0.0.0.0`), для PostgreSQL задать `DB_URL`.
